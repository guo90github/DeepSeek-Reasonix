## 附：本轮发生并已修正的一起行尾事故（必须记住）

**现象**：用 python 脚本给 `AppRuntimeView.tsx` 与 `floating-view-layer.test.tsx` 打补丁后，git 提示 `CRLF will be replaced by LF`，`git diff --stat` 出现 156 行的"虚假改动"。

**根因**：python 文本模式（`io.open(p, encoding='utf-8')`，`newline=None`）在 Windows 上**写入时把每个 `\n` 翻成 `\r\n`**；而本仓库标准是 **LF**（`.gitattributes` 强制 `text eol=lf`，`HEAD` 里该文件 CRLF 计数为 0）。因此一次"读—改—写"就把整个文件的行尾换掉。

**修正**：`git checkout` 该文件后用 **`newline=''`**（读与写都不翻译）重打补丁；未跟踪的测试文件与 `FloatingViewLayer.tsx` 用**二进制**替换 `\r\n` → `\n`。修正后 11 个前端相关文件的 CRLF 计数全为 0，`tsc --noEmit` / `eslint` / 两套测试仍全绿。

**纪律（已登记 A-29）**：脚本改仓库文件必须保行尾 —— 用 `newline=''` 或二进制读写；改完立刻 `git diff --stat` 核对行数是否与预期一致。
