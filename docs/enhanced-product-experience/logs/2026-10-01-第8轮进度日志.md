## 已完成

- ✅ **A-23 闭环落地**，语义链现在是：
  1. **起动**：`bash` 后台分支带出 `JobID`（新增 `tool.ShellExecution.JobID`）；宿主记 `jobID → 原命令`（`internal/agent/shell_job_receipts.go` 的 `shellJobCommands`）。
  2. **起动不算数**：起动那张回执被**降级**（`degradeBackgroundStartReceipt`：`Success=false` + 抹掉 `Command`）——既不再匹配"成功跑过"，也不再匹配"跑过但失败"。
  3. **收取**：`bash_output` / `wait` 现在**结构化**带出作业终态（`ExecuteDetailed` + `ExecutionDescriptor`），agent 在批次 `finalize` 里按 `jobID` 取回原命令。
  4. **记功**：终态 **completed** ⇒ 为原命令补一条成功回执，并在收取结果里写明 `collected as receipt r_… for \`<cmd>\` … cite it to sign this off`；**failed / killed** ⇒ 只记失败回执（不记成功）；**仍在跑** ⇒ 什么都不记。
- ✅ **测试**：
  - agent 单测：`TestCollectedBackgroundCheckCreditsTheCommand`（起动不记功 → 收取完成才记功 + 结果自述回执）、`TestFailedBackgroundCheckIsNeverCredited`（failed / killed / 仍在跑 三态均不记功）。
  - **真实装配 effect test**：`internal/boot/shell_job_receipt_effect_test.go::TestEffectCollectedBackgroundCheckBecomesAReceipt`（`bash(node --check note.js, run_in_background)` → `wait` → 断言 provider 边界上收到的收取结果带"cite it to sign this off"与命令原文）。
- ⚠️ **顺带查出两个真缺陷**（既有，但都决定第九是否可用）：
  1. **起动一张回执就能冒充"跑过"**：`bash(run_in_background)` 的回执此前是 `Success=true`+`Command=原命令` ⇒ `HasSuccessfulCommand` 在作业**未结束**时就为真，而 `completestep.go:300` 用它做验证兜底凭据 ⇒ 一条没跑完的验证可以被 `complete_step` 接受。修法=降级起动回执（登记 A-24）。
  2. **`DetailedExecutor` 是"两方法"接口**：只实现 `ExecuteDetailed` 而漏掉 `ExecutionDescriptor` 时类型断言失败、执行元数据**静默**为 nil（不报错）。第一版 `bash_output`/`wait` 正是如此，`go vet` 与组件单测都发现不了，靠真实装配 effect test 才暴露（登记 A-25）。
- ✅ **验证**：`go build ./...`=0；`gofmt -l` 干净；`go test ./internal/agent/ ./internal/tool/builtin/ ./internal/evidence/ ./internal/boot/` **四包全绿**（71.8s / 21.5s / cached / 162.7s）。
