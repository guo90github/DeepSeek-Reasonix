# 30 · 第十「标签页自由停靠」调研与设计（含第九档位控件合并定案）

> 阶段：第五阶段（桌面交互改造）· 类型：调研 + 设计（本轮只出设计；实作见 §7 顺序）
> 需求原话：实现桌面端多开——标签页不绑定应用主视图，可在窗口任意位置停留、缩放、自由拖拽。

## 一、现状事实（全部以源码为据）

| 事实 | 位置 |
|---|---|
| **标签页 = 工作区标签**：横向标签条，每个标签是一个已打开的项目/全局话题，"切换标签即切换当前会话" ⇒ 标签与**主视图**是绑定的（主视图同时只承载激活标签） | `desktop/frontend/src/components/TabBar.tsx:1-2` |
| 右侧 dock 另有**一套**标签壳（面板类型：文件树/预览/…），与工作区标签无关，勿混淆 | `desktop/frontend/src/components/TabContainer/TabContainer.tsx:1-6` |
| 布局几何（侧栏宽、右 dock 宽、折叠位）已是**可持久化的前端状态**，带夹取（clamp）常量 | `desktop/frontend/src/store/layout.ts:1-12`、`:16-40`，持久化走 `lib/layoutPreferences`（localStorage） |
| 已有"浮在布局之上的一层"：覆盖层宿主（历史/设置/回顾/垃圾箱/命令面板…），但**不可拖拽/缩放、无几何、无 z 序** | `desktop/frontend/src/app-shell/AppOverlayHost.tsx:38-59`，状态在 `store/overlays.ts` |
| 前端已有分隔条/指针交互先例（侧栏、底栏、dock 分隔） | `desktop/frontend/src/app-shell/SidebarRegion.tsx`、`FooterPanelBand.tsx`、`app-shell/dockRegionBuilders.ts` |
| 壳（Electron）只创建**一个应用窗口**；额外窗口的既有做法是**面向外部 URL**（独立 partition + 导航守卫），**没有**"同一应用把某个标签放进另一个窗口"的通路 | `desktop/electron/src/main/window.ts:72`、`desktop/electron/src/main/remoteWindows.ts:33-77` |
| 宿主侧已有窗口几何持久化先例（OS 窗口级） | `desktop/window_geometry.go`、`desktop/window_state.go` |
| **会话/标签在内核侧已多份并存**（多开在"会话"层已成立），缺的只是"**视图摆放**"这一层 | `desktop/tabs.go`、`desktop/tab_order.go`、`desktop/remote_tab*.go` |

结论：**"多开"的会话语义早已具备；本需求真正要补的是"一个标签的视图可以脱离主视图、并在窗口里自由摆放"**。

## 二、需求解读（逐条对应）

| 需求措辞 | 落点 |
|---|---|
| 多开 | 多个视图**同时可见**（今天的"多开"是标签切换 + 分栏，多个会话并不都能同屏自由摆放） |
| 标签页不绑定应用主视图 | 标签可脱离"被主视图承载"的二元状态：撕下后由浮动面板承载 |
| 可在窗口任意位置停留、缩放、自由拖拽 | 面板几何（x/y/w/h）+ 拖拽 + 缩放 + 停靠（snap）+ 几何持久化 |

## 三、方案与取舍

| 方案 | 形态 | 利 | 弊 |
|---|---|---|---|
| **A. 壳内浮动面板层** | 在既有布局之上加一层"视图面板"：标题条拖拽、边/角缩放、可停靠回主视图；标签被"撕下"即由面板承载 | 满足"窗口内任意位置/缩放/拖拽"的字面要求；几何/持久化沿用前端既有路线；不动壳，风险面小 | 不是原生 OS 窗口，"拖到桌面另一处"做不到 |
| **B. 每标签一个 OS 窗口** | Electron 为标签开 `BrowserWindow`，OS 负责拖拽/缩放，几何走宿主持久化 | 原生手感、可跨显示器 | 需要"单 surface 模式"路由、每窗口的 host bridge/会话订阅、标签注册表同步；`remoteWindows.ts` 那套是给**外部 URL** 的，不能直接复用；打包与权限面变大 |
| **C. 混合（推荐）** | 先落 A；把"摆放"抽成**一份记录**（§4），B 作为该记录的另一种宿主（窗口只是 surface 的一种） | 一次设计到位，避免两套摆放模型；A 可独立交付 | 记录要一次想清（见 §4 的纪律） |

**选定：C 的形态，本批先落 A。** 依据：需求字面是"窗口任意位置"（A 即可满足），B 的价值是"跨显示器/原生窗口"，可在同一份记录上后补；先落 A 才能让"撕下/停靠/持久化"这些真正难的东西在有界范围内做完。

## 四、状态模型与两条硬纪律

```ts
// 视图摆放：一个工作区标签的视图此刻在哪儿
type ViewPlacement = {
  viewId: string;                    // 工作区标签 id（TabMeta.id）
  surface: "main" | "float";         // 未来加 "window"
  rect: { x: number; y: number; w: number; h: number }; // surface="float" 才有意义
  z: number;
  docked: "none" | "left" | "right" | "bottom";
};
```

1. **一个视图在任一时刻最多被一个可见 surface 承载**（撕下=**移动**，不是复制）。
   理由：同一会话被两个渲染实例承载会产生双份滚动写者、双份流式订阅与输入焦点冲突——项目对"滚动/流式写者单一化"已有既有纪律与守卫（`desktop/frontend` 的单一滚动写者检查）。
2. **几何持久化沿用前端既有路线**（`store/layout.ts` 的 localStorage + clamp 口径），OS 窗口那部分将来再走宿主（`window_geometry.go` 先例）。**不把面板状态写进系统提示或工具面**——档案明确要求系统提示前缀字节稳定（缓存优先）。

## 五、依赖与风险

| 风险 | 说明与缓解 |
|---|---|
| R-14 拖拽与文本选择冲突 | 只允许**标题条**发起拖拽，并在拖拽期间 `setPointerCapture` + `user-select: none`；面板正文保持可选择 |
| R-15 焦点/z 序混乱 | `z` 单调递增写入记录；点击面板将其提到最前；键盘焦点进入面板时不动 z（避免与流式刷新互相干扰） |
| R-16 与分栏（split）叠加 | 分栏是 **main surface 内部**的布局；浮动面板是 main 之外。规则：把某标签撕下时，若它是分栏之一，先退出分栏再浮动 |
| R-17 持久化与多显示器 | A 阶段只记录窗口坐标系的矩形并夹取到可视区；跨显示器留待 B |
| R-18 面板太多 | 首版设上限（如 4 个浮动面板）并在超出时提示；上限值可后调 |

## 六、验收标准（可测）

1. **拖拽/缩放**：标题条拖拽移动、拖四边四角缩放；越界被夹取（不低于最小尺寸、不超出可视区）。
2. **撕下与停靠**：撕下 → 浮动 → 停靠回 main，往返后**会话状态不丢**（滚动位置保持、正在流式的输出继续追加）。
3. **持久化**：刷新/重启后每个浮动面板的位置与尺寸恢复。
4. **单承载纪律**：任一时刻同一 `viewId` 的可见承载数恒为 1（用渲染实例计数断言）。
5. **多面板并行**：同时开 3 个不同会话的浮动面板，各自继续流式、互不串流、互不抢焦点。

## 七、批次定案：第十 / 第十七 / 第九档位控件

顺序（每步独立可验收）：

1. **第十-A1**：浮动面板层 + 拖拽/缩放 + 夹取 + `ViewPlacement` 记录 + localStorage 持久化（先只支持"从主视图撕下"，不支持多面板）。
2. **第十-A2**：停靠（吸附四边）+ 多面板 + z 序/焦点 + 快捷键 + 上限提示。
3. **第十七**：待办队列（内核状态机，见立项书假设 A-08）；其面板挂载点按第十的新模型摆放。
4. **第九档位控件**（小，可并行）：挂在**设置页（通用）**而非工具/提示面（缓存约束）；档位=已有配置键 `shell_async`；控件必须写明**重启生效**（R-11）；验收复用本文档 §7.3 的三档实测表（改档后同一场景的往返间隔可测）。
5. **（后续）第十-B**：同一份 `ViewPlacement` 记录 + OS 窗口宿主（需先补"单 surface 路由"与每窗口 host bridge）。

**本轮不改壳**（Electron 主进程零改动）；B 阶段才动 `desktop/electron/src/main/window.ts` 一侧。

## 十、A1 接线记录（2026-10-01 第 11 轮）

### 10.1 一处事实更正（必须先说）

§9.3 里我写的「现成的第二视图通路是分栏（`lib/transcriptPanes.ts` + `components/SplitWorkspace.tsx`）」**是错的**：

- `SplitWorkspace` 是**同一个标签**的两栏（conversation pane + process pane），不是第二个标签的视图；
- `useTranscriptSurfaceProjection` 里的 `visibleTranscriptSurface` / `visibleTranscriptTabId` 是**切标签时的绘制闸门**（`transitioning && !navigationDataReady && preserved` 时短暂保留上一标签的项，随后 `commitSingleSurface`），不是常驻的第二面。

⇒ 壳里**没有**「第二个标签的视图通路」。给任意后台标签渲染完整聊天面板需要把 `ChatPaneRegion` 那套 region props（`chromeRegionBuilders` 等）按 tabId 参数化，属结构性改动。**因此 A1 的接线按"撕下当前标签"落地**（与需求"A1 只支持撕下单个面板"一致），后台标签的面板先给"切到该标签"的提示。
