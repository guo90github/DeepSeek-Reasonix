## 二、方案

### 2.1 一件共享产物：`TurnOutcome`（会话态）

- **形状**（内容无关，落在与召回/技能同一张会话侧车 `BranchMeta`，同一纪律：上限、同回合替换、正文不入）：`{TurnSeq, Verdict, MissingObligations[], MissingCounts{}, RecoveredFailures, ChangedFiles, ConclusionEntries}`。
  - `Verdict` ∈ `delivered | blocked | aborted`，直接由审计结果映射（`ReadinessAllowed`→delivered、`ReadinessBlocked`→blocked、`ReadinessErrored`→aborted ✓ 枚举见 `internal/evidence/readiness_audit.go:7-9`）。
  - **`MissingCount` 先落（审计自带计数）；`MissingIDs` 需要 agent 侧开一个访问器**（`finalReadinessCheck.missingIDs()` 目前不外露）⇒ 列为 BA1b 的一部分，本轮记录里该字段留空。
  - `ChangedFiles` 是**计数**（不是路径清单，避免把工作区内容塞进记录）；`ConclusionEntries` 是本回合落下的结论条目数。
- **写法**：在既有"回合结束"链路上追加一步（`finishInFlightTurn` 之后 / `todo_settle` 同处），**不新增钩子**。

### 2.2 后置强化（post）

1. **收尾核对**：沿用 `final_readiness`（已有），把结果**同时**写成 `TurnOutcome`（新增：结果落档 ✓）。
2. **一次性收尾动作**（已决：开，见 U-5）：`delivered` 且本回合有新结论 ⇒ 生成一条**记忆候选**（复用 `memory_suggestions` 机制，人确认后才落盘）。理由：这正是"结论固化"的低风险形态，且已有先例。
3. **不做**：不接受"自动写记忆/自动改提示"（违反 D-6 与第七的门槛）。

### 2.3 前置强化（pre）

- **形态**：回合**尾**（不是前缀，D-1）注入一个**有预算**的"进度与义务"块，内容＝最近 K 轮 `TurnOutcome` 摘要 + 当前未满足义务（若门禁已算出 `missingIDs`）。默认最多 3 轮，超了先丢最旧轮次（U-4 已决：不设字符上限）。
- **为什么放回合尾**：与 memory-update / recall / background-jobs 完全同构（`docs/50` §1.5 的既有纪律），前缀保持字节稳定。
- **可选第二批（U-4）**：把**仓库变更态**做成一条**缓存探针**（`git status --porcelain` 的计数摘要，30 秒 TTL）并入该块；代价是每次可能多一次命令，收益是模型少跑一轮 `git status`。默认关。
- **不做**：不把面板/档位/归档态塞进提示（D-3）。

## 三、状态模型与纪律

| 状态 | 归属 | 生命周期 | 出口 |
|---|---|---|---|
| `TurnOutcome`（持久，会话态） | `BranchMeta.TurnOutcome`（≤200 回合） | 会话 | 前端/回顾页；**前置块**的输入 |
| 前置块（派生，每条一次） | 回合正文（临时） | 单轮 | 只进当轮正文，绝不进前缀 |
| 就绪审计（宿主侧） | `evidence.ReadinessAudit` | 单轮 | 保持"非渲染"（不回灌提示），只喂 `TurnOutcome` |

- **D-1**：一切新增内容走回合尾或侧车，前缀与工具面保持逐字节不变（effect test 兜底）。
- **D-3**：面板/档位/归档态不进提示；前置块只放**模型自己产出或宿主已判定**的事实（义务、轮次结果）。
- **D-6**：`TurnOutcome` 与前置块都内容无关（计数、id、短枚举），命令文本/文件路径/结论正文一律不入记录；前置块里若要引用文件只放**计数**。
- **预算**：前置块默认最多 K=3 轮、不设字符上限（U-4 已决）；`TurnOutcome` 上限 200 回合（与召回/技能记录一致）。

## 五、未定与风险

- **U-4（已决，用户 2026-10-01）**：前置块**默认开、最多 3 轮**；用户未设字符预算 ⇒ **不加字符上限**（若 TTFT/成本被量出问题再加）。仓库变更态缓存探针维持**默认关**。
- **U-5（已决，用户 2026-10-01）**：后置在 `delivered` 后**自动建议**记忆候选；落地时按 R-48 去重 + 每会话上限。
- **R-46**：前置块本身会占用**每轮** token；必须与小模型/长会话的 prefill 成本一起量（参见本仓库"长会话首反馈延迟"的结论：TTFT 随上下文增长）。**未量**：前置块对 TTFT 的边际影响（预计极小，但要量）。
- **R-47**：`TurnOutcome` 的 `Verdict` 依赖就绪门禁的判定；若门禁语义以后变动，记录口径要跟着改（需在实现处写清来源）。
- **R-48**：BA4 若开启自动建议，需防"每回合都建议同一条结论"（按结论 id 去重 + 每会话上限）。
