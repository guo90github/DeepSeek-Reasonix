## 二、方案

### 2.1 热力图（第十四的主体）

- **形态**：日历热力图（行＝项目，列＝最近 `insightWindow`（30 天）的日格），格强度 ＝ 当日该项目的洞见条数（`Occurrences` 按 `Projects` 归并）+ 当日生成的回顾条数。
- **数据**：`ListSessionRecaps`（每条的 `GeneratedAt` + 项目）与 `ListRecapInsights`（`Projects`/`Occurrences`/`SeenAt`）**在现有 RPC 上聚合**，不新增 RPC；聚合逻辑放前端纯函数（`lib/recapHeatmap.ts`）⇒ 可被 `tsx` 直接单测，不需要 DOM。
- **交互**：点格 ⇒ 过滤该日/该项目的回顾行（复用页面既有列表，不新开页面）；空格不渲染空提示。
- **可访问性**：每格带 `aria-label`（日期 + 条数），键盘可聚焦；颜色走既有 token（**禁用已退役 token**）。

### 2.2 第十六的"召回/技能记录"落点

- **落点＝回顾页的会话详情区**（"加入现有面板模块"而不是新开页面）：一行摘要「本轮召回 N 条（M 条被挤掉）／用了技能 X」，点开列指纹（`id`/`revision`/`score`/`injected`、技能 `name`/`contentHash`/`catalogDigest`）。
- **数据**：`RecallRecordForTab(tabID)`（本轮已加并在契约里生成）。
- **纪律**：面板只读；记录里**没有**记忆/技能正文，前端也**不得**回填正文（与 `docs/50` §3.2 D-6 一致）；面板状态（展开/折叠）只在本机，不进提示、不进工具面。

### 2.3 不做什么

- 不新增顶层页面（第十四说的是"现有页面深化"）；不改 `internal/recap` 的生成提示词（那是另一个已交付的功能面）。
- 不改任何进系统提示的内容（本条纯读数 + 前端渲染）。

### 2.4 页面形态与高度契约（2026-10-01 补，第十四）

**问题（用户人眼验收）**：“条数多了以后，有些模块全文铺展，有些被挤成一小截看不到。”根因不是某条样式，而是**这页没有唯一的滚动所有者**：`ManagementPageShell.css:12` 的内容卡片是 `overflow:hidden` 的固定高度纵向 flex 容器，而页面把热力图、洞见、未完成项、工具条、预览、待生成、旧规则与卡片列表**平铺为同级 flex 子项**；只有卡片列表写了 `flex:1; min-height:0`（`SessionRecapPage.tsx:566`），于是它成了全容器里**唯一能被压到 0 高**的子项：条数一多（未完成项/旧规则/洞见行数不受控）就先牺牲列表，溢出的部分又被 `overflow:hidden` 裁掉。

**契约（落地后）**：

| 段 | 内容 | 高度契约 |
|---|---|---|
| 头部（固定） | 状态条 + 工具条（搜索/排序/计数/展开折叠）+ 空结果提示 | `flex:0 0 auto`、`max-height:33vh`、自带滚动 |
| 概览面板（封顶） | 热力图、跨项目洞见、未完成项、待生成、旧规则、预览面板 | `flex:0 1 auto`、`max-height:40vh`、`overflow-y:auto`（可被压到 0） |
| 列表（唯一滚动区） | 回顾卡片 | `flex:1 1 auto`、`min-height:160px`、`max-height:none`、去掉借用 `.history-list` 带来的 40vh 与右边框 |
| 行内细节 | `RecapRow` 的 `detail`（依据/范围/来源/引用） | 折叠时一行省略（文本仍在 DOM，可复制可搜索），展开时换行 |

**规则**：*只有列表允许随条数变高；其余模块要么封顶、要么自己内滚。*新增同级区块前先问它属于哪一段。

**与初版设计的两处偏差（均为取舍）**：
1. **不做卡片手风琴**：初版设计写了“同时只展开一张卡”，但那与既有产品意图冲突（`recap-expand-all` 全部展开，页面测试锁定）。列表成为唯一滚动区后，展开的卡片只是列表内容变长，不再挤出任何东西。
2. **预览面板不做覆盖层**：改为放进封顶面板内（`max-height:40vh`）。覆盖层需要新的 scrim 令牌与焦点陷阱，而 `check-theme-token-contract` 会校验全部 CSS 文件；高度问题已由封顶解决。

**同批修复的缺陷**：本地日分桶（R-46）、日格筛选缺出口、同话题组的勾选/撤销不对称、每张卡一次 `recallRecord` 读、定时器无清理且批量放大、刷新依赖 prop 身份、`queued` 标签永不清、空态两条重叠提示、分组只能展开不能收起、参数 `list` 遮蔽同名 prop。

## 三、状态模型与纪律

| 状态 | 归属 | 生命周期 | 出口 |

| 回顾条目/洞见（持久） | 会话侧车 + 洞见报表 | 跨会话 | `ListSessionRecaps` / `ListRecapInsights` → 页面 |

## 五、未定与风险

- **U-3（已决，用户 2026-10-01）**：维持现状——默认窗口 **30 天**、粒度**日格**。若要按"周"或按"最近 N 个会话"呈现，另开一条。
- **R-43（已按设计处置）**：`SessionRecapPage.tsx` 接入只增 **+5 行**（两个 import、一个状态、一处挂载、过滤条件就地改写），全部新逻辑在独立组件/纯函数文件里；repolint 未对该页报新账（它仍在自身预算内）。
- **R-45（新，教训）**：给 memo 化的过滤链新增条件时**必须同时补依赖数组**——B6c 首轮漏了 `heatmapDay` 依赖，组件级测试全绿而**页面级测试**才抓到（选择日期后列表不收敛）。凡"新增过滤/排序输入"，页面级交互断言是必需的仪表。
- **R-44**：洞见 30 天窗口意味着热力图"空列"可能只是窗口裁剪，不是"没干活"——UI 必须标出窗口边界，避免误读。
- **R-46（新，根因）**：热力图按 **UTC** 日分桶（`dayKey` 用 `toISOString()`），而卡片上的时间用 `toLocaleString()`（本地时区）——UTC+8 下本地 00:00–08:00 生成的回顾会落在**前一天**格子里，与旁边写着后一天的卡片互相矛盾。已改为**本地日历日**（`lib/recapHeatmap.ts:dayKey`），测试改为按本地日推导（不再硬编码日期，任何时区都能跑）。教训：“日”必须和“页面上显示的那一天”同源。
- **R-47（新，教训）**：辅助区块平铺进固定高度 flex 容器的写法，使**任何新增区块自动参与挤压**，且牺牲的总是唯一可压缩的那个（历史上是列表）。新面板落位前先确定它属于“固定 / 封顶 / 滚动”哪一段（§2.4）。
