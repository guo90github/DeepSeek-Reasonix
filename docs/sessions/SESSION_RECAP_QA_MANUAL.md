## 1. 最小闭环（约 5 分钟）

**目标**：一次关闭 → 页面出现一条能看懂的候选条目回顾（若干条"可复用的话"），且敏感串被遮蔽。

1. **造样本**：新建一个会话，聊 2–3 轮。内容里**故意**写进：
   - 内网地址：`http://10.20.30.40:8080/admin`
   - 假 token：`sk-test-1234567890`
   - 明确待办：`明天给 X 模块补回归测试`
   - 一句结论：`原因是 A，不是 B`
2. **等回合彻底结束**。关闭前确认**三项都为空**（否则走"分离"，见下表）：
   - 没有在飞的回合（输入区没有"停止"）；
   - 没有待应答的提问/审批；
   - 后台作业面板里没有"运行中"的作业。
3. **关闭这个会话**（四个入口同源）：`Ctrl+W`（关闭标签页）；或标签总览菜单 **关闭标签页 / 关闭其他标签页 / 关闭右侧标签页**。
4. **看回顾**：侧栏「会话回顾」。列表为空就点右上 **刷新**（要真调一次模型，几秒）。
5. **预期**（逐项打勾）：
   - [ ] 卡片首行是 **会话标题 / 轮次 / 生成时间 / 模型**，下面按**条目**逐行列：每条前置 `类目 · 建议落点`（事实 / 根因—修法 / 否证结论 → `→ 记忆`；交接与未解坑 → `仅提示`），后接正文；有出处时以括号附在正文后
   - [ ] 条目读得懂：哪个会话、干了什么、结论是什么、还剩什么
   - [ ] **该会话没有可复用的结论时**：卡片只显示一行「**本次会话没有可沉淀的结论**」，不出现空行占位
   - [ ] **`sk-test-1234567890` 与 `10.20.30.40` 都已遮蔽**（显示 `[redacted]`，正文与出处都要看）
   - [ ] 「模型」= 该会话当时用的模型
   - [ ] 副标题为「只含会话关闭时生成的会话回顾；会话本身的删除、恢复在回收站。」＋ 采纳说明
6. **逐条采纳**（这一步才有产出）：
   - [ ] 可采纳的条目给三个按钮：**采纳 / 改后采纳 / 弃**；`交接与未解坑` **只展示、没有按钮**
   - [ ] 点「采纳」→ 条目出现**已采纳**，并且**在「设置 → 记忆」里出现同一条事实**（这是"采纳真的落地了"的唯一判据）
   - [ ] 点「改后采纳」→ 出现编辑框，改完「保存并采纳」→ 记忆里是**改过的正文**
   - [ ] 点「弃」→ 出现**已弃**；此后**同一会话重新生成回顾时该条不再出现**（按内容哈希记住）
   - [ ] 点「撤销」→ 回到未处理态（**记忆里已写入的事实不会被撤销**，要去记忆页删）
   - [ ] 写入失败时页面报错、条目**保持未处理**（不假装成功）
   - [ ] 会话**不属于当前项目**（卡片只有文件名）时，条目**没有按钮**——采纳写的是当前项目的记忆，跨项目只读
   - [ ] 条目现在带**依据（指针）**与**模型提议的落点**：行下有一行 `path desktop/x.go L40 · command go test ./…`，行上有一句「模型提议落点：generic（采纳仍写当前项目）」；**采纳后记忆的事实里也带 `**Pointers:**` 与 `**Scope proposed:**`**，而落点**仍是当前项目**——写全局要显式开关，现在没有
   - [ ] **同一结论被两个项目独立得出**时，行上多一句「另有 N 个项目独立得出同一结论：<桶名>」；只在一个项目出现过的结论**没有**这句（这是"通用级"唯一可核对的依据；数的是投影里的条目，不是模型的话）
7. **登记并送达未完成项**（`交接与未解坑` 的专用通道；它**不进记忆、不写文档**）：
   - [ ] 该条目的按钮是**「登记为未完成项」**（不是采纳/改/弃）；点完变成**已登记**，且页面顶部出现「**本项目未完成项**」列表里有它
   - [ ] 列表里点「标记已处理」→ 该行**变淡并显示已处理**（仍留着，可「撤销」）；这正是"项目不匹配/没命中时不投递"的安全网：没被提示也能在这里看到
   - [ ] **送达判据**（三个闸门同时成立才可能提示：**同项目 ∧ 话题命中 ∧ 未处理**）：新建一个**同一项目**的会话，第一句话就提这件事（**两个**原条目里的文件名，或一个文件名加 4 字以上的原话）→ 该轮应出现一段 `<open-items>` 提示，**内容是"看起来是这件事，要不要继续"的提问**，且**原有输入文字一字不少地保留在后**
   - [ ] **反向**（这几条必须**都不出现**提示）：
     - 同项目新会话，第一句话是**别的事** → 不提示
     - 同一项目里只提**一个**原条目里的文件名（哪怕这个文件确实相关）→ **不提示**：一个文件名在同项目里是普通重合，2026-09-30 实测此条单独会让 39.5% 的无关开场白命中
     - 已被你标为**已处理**的那条 → 不提示
     - 在**别的项目**的新会话里提同一句话 → 不提示（项属于原项目）
     - 已在跑的**会话中途**（不是第一轮）说这句话、且没有"接着/继续/上次/未完成"这类字眼 → 不提示；补上这类字眼 → 提示
     - **超期的那条**（登记满 30 天后再提同一句话）→ 不提示；同时它在「本项目未完成项」列表里**仍在**、行上多一句「太久没动 · 不再自动提示」，计数行出现「其中 N 条太久」；点「撤销」再重新登记（或重跑回顾再登记一次）→ 又能提示
   - [ ] 全程**没有为它发生任何模型调用**（用途面板里不出现额外的 `session-recap`）——判据是**本地匹配**，不是模型判断
8. **生成失败的可见性**（失败时**没有记录**，只能靠待补标记列出；这是"静默失败"的唯一出口）：
   - [ ] 把回顾模型指到一个不可用的档位（或断网）→ 关闭一个会话 → 回顾页顶部出现「其中 N 条还没生成成功，正在等重试」，该会话那一行显示「生成失败（第 N 次尝试）：原因」与「最近尝试于 …」（行没有条目）
   - [ ] 该行**不显示**「本次会话没有可沉淀的结论」：两种沉默必须分开（`recap_pending` 有行 = 生成失败；成功但 0 条 = 真的没有可沉淀的结论）
   - [ ] 原因里若含密钥/内网地址，页面上是**脱敏后**的文本（宿主出站前再过一遍 `secrets.Redact`，不依赖写入时那次）
   - [ ] 模型恢复后点该行的「**重试生成**」→ 行上出现「已排队生成，稍后刷新查看」（车道是异步的，页面不会假装有结果），稍后刷新 → 计数与黄条消失、条目出现，且 `recap_pending` 里该行已被清掉
9. **手动生成给"从来没有回顾"的会话**（`list` 里既无记录也无失败行的会话在上面根本不会出现，所以要有这个入口）：
   - [ ] 回顾页出现「**还没有回顾的会话（最近 N 个）**」段，列出最近 5 个没有回顾的可见会话（带标题）；更早的会话不在其中，要点是提示用 §5 的 `catalogs reindex session-recap` 批量补
   - [ ] 点某行的「生成回顾」→ 行上出现「已排队生成，稍后刷新查看」；稍后刷新 → 该会话带着条目出现在下面的回顾列表里
   - [ ] 生成走的是**同一条车道**（关闭路径那条）：用途面板里只有 `session-recap` 一个来源，不会出现第二条用量线；排队拒绝（车道未启动/队列满/同路径已在队列）时页面报错而**不是**假装已排队
10. **早前结论以背景形态随轮次到达**（T1；与未完成项同一批闸门，但**不是提问、不派活**）：
   - [ ] 同项目里已有一条 `refuted` 或 `root-cause` 条目（**未采纳也未弃**）→ 新建同项目会话，第一句话里点名该条目引用的**三个**标识符（文件/命令）→ 该轮出现 `<prior-notes>` 块，内容是"这是你没要的背景、可能过时或错、以你现在看到的为准、**不要回答它**"这种口径
   - [ ] **反向**：该条目**已被你弃**（或已采纳）→ **不出现**；只共用语词、没点名标识符 → 不出现；跑着的中途轮次只共用语词 → 不出现；别的项目的会话 → 不出现；最多只带 **2** 条
   - [ ] 原有输入文字**一字不少**地在块之后（背景骑回合尾部，不改系统提示前缀）

**怎么复测命中率（校准，不改任何东西）**

判据是本地词面规则，阈值只能靠真实语料校准。这个探针把**已生成的回顾笔记**当候选条目，对**同项目其他会话的真实开场白**回放，打印召回与误放行率；它只读状态根，只写你指定的那份投影副本：

```bash
cp "%LOCALAPPDATA%\reasonix\session-recap\v1.sqlite" <临时目录>\v1.sqlite
RECAP_CALIB_DB=<临时目录>\v1.sqlite \
RECAP_CALIB_ROOT="C:/Users/<你>/AppData/Roaming/reasonix" \
  go test ./internal/recap/ -run CalibrateOfferRule -v -count=1
```

- **必须指向副本**：这份投影会被 `Open`（含 schema 迁移）。**绝不要指向正在用的 `v1.sqlite`**——2026-09-30 就是因为少给一个变量、落回真实缓存路径，一次运行把 v1–v3 时代的回顾行迁没了。两个变量缺一个就直接跳过。
- 副本里没有回顾行时打印「holds no records」后跳过（要先用 §5 的 `catalogs reindex session-recap` 给副本灌几行）。
- **2026-09-30 实测**（13 条真笔记 × 598 条同项目无关开场白，全部在真实会话上回放）：旧判据「1 个标识符即算」误放行 **39.5%**；现判据「**三个**标识符 / 一个标识符+两处片段 / 三处片段」**13.2%**，召回同为 9/13。判据空间扫过一轮的结论：**收紧片段数是最贵的旋钮**（片段下限 3→4：误放行 12.2%，召回却从 9/13 掉到 4/13），**标识符条数便宜**（2→3：同召回、误放行 15.7%→13.2%），所以动的是标识符条数。残余误放行里大头是纯片段命中（`ids=0 pairs=3` 占 22%）与「1 个标识符+2 处片段」（16%）。**再往上就崩召回**：最严一档 5.4% 误放行只剩 3/13 命中——**阈值到不了 ≤5%，这是实测的天花板**。
- 稀有度（一个"全项目都在提"的文件名不该算证据）实测：把**在 ≥3 个同项目会话里出现过**的标识符判为普通后，误放行 13.2% → **9.5%**（召回 9/13→8/13）；阈值放到 ≥60 就没效果。方向对，但生产侧**还没有这份语料**（`recap_resume.head_text` 只覆盖被回顾过的会话），要建才能用。
- **"用会话标题当语料"已实测否掉**（2026-09-30，用户指定先试这条）：把本桶 48 条标题里的词频当"普通词"判据，阈值 1/2/3 全部**一格不动**（13.2% ↔ 13.2%，召回 9/13 不变）。原因查清了，是结构性的：**13 条笔记里的 52 个标识符，在 48 条标题里出现 0 个**（标题是"这个会话要干什么"的口语一行，48 条里只有 4 条含路径）。⇒ 判据要的语料必须**含路径/命令本身**，标题天生不含，这条路不用再试。
- 口径：**误放行率可直接决策**；召回的分母是「笔记对自己会话的开场白」，只作下界参考。

**开关语义对照（该生成 / 不该生成）**

| 动作 | 是否生成回顾 |
|---|---|
| 空闲关闭（上表三项皆空）本标签 / 关闭其他 / 关闭右侧 / 关闭标签页 | ✅ 生成 |
| **任一"活跃"项非空时关闭 → 分离**（作业进"后台作业"继续） | ❌ 当次不生成；且分离的运行时**之后不会被自动关闭**（只有"关闭项目工作区"或"退出 App"才 `Close()`）⇒ 该会话基本等不到回顾，用 §5 补录 |
| 恢复会话后**未在本进程跑过回合**就关（`< c2f6c67aa` 的包） | ❌ 不生成（`started` 闸门）；装带 `c2f6c67aa` 的包后即可生成 |
| `/clear`、新建会话轮转 | ❌ 不生成（丢弃类动作，boot 侧按 reason=clear 拦下） |
| 归档到回收站 / 彻底删除 | ❌ 不生成（文件被移走，指纹取不到） |
| 重复关闭同一会话（内容未变） | ❌ 不重复（指纹 + 提示词版本幂等） |
| 二次打开**跑过活跃任务**后再关闭 | ✅ **覆盖更新**同一行（`recap_records.path` 是主键，upsert）；不是新增一份 |
| App 退出 | ⚠️ 会给运行时发 `Close()`，但进程随即终止、不等回顾 ⇒ 当次丢 |

```bash
# 待补队列（有行 = 该会话还没生成成功，原因见 last_error）
sqlite3 "$DB" "select path, attempts, last_error, datetime(updated_at/1000000000,'unixepoch','localtime') from recap_pending;"

# 决策留痕（需要含决策留痕的包；这是排查"为什么没生成"的第一仪表）
sqlite3 "$DB" "select datetime(at/1000000000,'unixepoch','localtime'), stage, detail, path \

sqlite3 "$DB" "select kind, choice, body, datetime(decided_at/1000000000,'unixepoch','localtime') \
  from recap_decisions order by decided_at desc;"

# 回顾那次调用的用量（用途标签写在当日 stats 原始行里，不在面板）
rg -o '\{[^{]*"usage_source":"session-recap"[^}]*\}' "C:\Users\guosj\AppData\Roaming\reasonix\stats\<日期>.jsonl"
```

**保留策略（宿主每次启动建车道时跑一次，日志里能看到）**：投影是缓存，所以它会自我修剪——`recap_records` 删 180 天前的记录、`recap_resume` 删**会话文件已不存在**的行、`recap_activity` 只留最近 500 行；有删除时打印 `session recap projection pruned records=… resumes=… activity=…`，没删就不打印。**`recap_decisions`（采纳/弃）与 `recap_open_items`（未完成项）永不清理**：那是人产出的，不是派生数据（单测 `TestPruneKeepsWhatThePersonProduced` 钉住这条）。`head_text` 不需要上限——写进去时已被 `headPiece` 截到输入预算的 3/5。

**怎么读决策留痕**（这是三次排查换来的判据）：

| 留痕 | 含义 |
|---|---|
| 完全没有该会话的 `generate` 行 | **关闭没有上报结束事件**（最可能是"分离"，或旧包的两个已修缺陷） |
| `submit` + `rejected: empty path` | 关闭时路径已被清空（`b2d7fbe43` 修的缺陷） |
| `submit` + `rejected: discarded` | `/clear` 或新建会话轮转，按丢弃语义跳过 |
| `submit` + `rejected: already queued` / `queue full` | 车道忙/队列满，稍后由补录捡回 |
| `generate` + `skip: current` | 内容没变且提示词版本一致 → 幂等跳过（正常） |
| `generate` + `skip: empty transcript` | 该会话没有可回顾的正文 |
| `generate` + `skip: <其他>` | 见 `recap_pending.last_error` |
| `generate` + `stored` | 已落盘；若页面仍空则是展示面问题（看 §3.1 的可见集合口径） |
| `fastpath` + `verified` | 每进程前 2 次关闭会把"直读转录"与"权威重放"对一次账：一致 |
| `fastpath` + `mismatch: took the replay` | 两者不一致 ⇒ 已改用重放结果（并留痕），据此可判定直读不可信 |
| `fastpath` + `authoritative read failed` | 对账时重放失败，沿用了直读结果 |

## 4. 通道隔离（本功能最硬的一条：不许打扰会话）

**口径**：回顾的调用路径不得与会话抢占/共用，不得影响会话链路。

1. **关闭要"瞬间"返回**：关闭一个有若干轮历史的会话应立即完成（回顾在后台跑），加载圈不逗留。
2. **生成期间照常聊天**：关闭后马上在别的会话持续对话——消息时序、首字延迟、用量都应无变化（回顾用**独立 provider 实例**，不取会话租约、不进会话准入）。
3. **用量分账（2026-09-30 已落地）**：回顾那次调用有自己的用途标签（当日 `stats\<日期>.jsonl` 里 `"usage_source":"session-recap"`，如 `2026-09-30.jsonl` 09:38:20 那条），现在**在设置 → 用量统计面板底部有「按用途」分区**（U1a 已落地：面板多一段按 `usage_source` 的 token 占比，行名即用途 id，如 `session-recap` / `executor` / `title`；用途与「入口点」是两个正交维度，面板顶部的来源筛选仍只按入口点）。核对命令仍见 §2 末条。
   仍未修：该条目报价为 `no_price`（`display_status: unavailable`）⇒ 回顾调用目前**没有计价**，所以「按用途」里能看到它的 token 占比，但**费用列不参与**（U3 待做，牵动共享的 `boundedllm` 与定价装配）。
4. **不进系统提示前缀**：会话系统提示与工具清单不因本功能改变（无新增 Agent 工具、无 tool schema 改动）。
5. **转录读取的两阶段（阶段 2 已落地）**：第一次关闭走"直读"（摘要可证）或重放，并把"读到哪、头部是什么"记进投影的 `recap_resume`；**同一条会话的下一次关闭只解析新增行**，与保留下来的头部合并后再裁剪。三道闸门任一不成立就整段回退（前缀哈希不符 / 侧车摘要没推进，即"只追加了行却没保存" / 新增行解析失败，另有 pinned context revision 与无侧车两类老规矩），所以**"回顾更新了"不等于"走了增量读"**——真机肉眼分不出来，确认靠本地测试 `internal/recap/resume_test.go`（等价性 + 两道拒绝证明 + 一条断言"通道真走覆盖读"的效果测试）。真机侧唯一可见的是 `recap_activity` 的 `resume` 行，且**只在记录失败时**才写（投影写不进 ⇒ 下次关闭退回整读，功能不受影响）。
6. **记录变多时的页面行为（2026-09-30 落地）**：列表自带滚动（`.history-list`），每张卡带会话标题 / 轮次 / 本地化生成时间与**打开会话**按钮（会话不在可见列表里时只有文件名、无按钮）；工具条可按标题与四要素**搜索**、按最新 / 最旧 / 会话名**排序**。验证口径 = 本地测试 `desktop/frontend/src/__tests__/session-recap-page.test.tsx`（滚动容器、标题关联与文件名回退、三种排序、搜索命中与无命中、打开会话会 resume 并离开本页）。仍未做：取数仍是一次拉全量（无分页 / 虚拟滚动），`recap_records` 只增不减，`recap_resume.head_text` 无保留策略。
