# 推理稽查 — 手动验证指南

本指南逐步带你完整手动验证推理稽查功能（独立 evaluator + 跨 Tab 聚合 + 低分提醒）。
请针对**已包含该功能的打包客户端**执行。

> **开始前** — 必须配置 evaluator 模型，否则审计会静默跳过。确认客户端已含本功能，且：

```toml
[agent]
audit_model = "<你的评估模型 ref>"   # 例如 "deepseek-v4-pro"；必须非空
audit_enabled = true
audit_threshold = 0.6

[notifications]
enabled = true
audit_below = true        # 低于阈值发送系统通知
```

> 关键点：`audit_model` **不能为空**，否则 `AnalyzeReasoning` 返回
> "audit model not configured"，整个功能静默失效。它经独立 `AuditProviderResolver`
> 解析，**绝不会**用会话模型。

---

## A. 模型隔离（独立性）

**目标**：审计用独立模型，绝不影响会话模型。

| 步骤 | 操作 | 预期 |
|---|---|---|
| A1 | 正常发起一个让模型思考的回合 | 回合照常进行，**无额外延迟或中断**（审计在 TurnDone 后异步跑，热路径之外） |
| A2 | 回合结束后观察约几秒 | 出现审计结果（红点/通知），证明独立 evaluator 在后台跑了 |
| A3 | 连续跑多个回合 | 会话思考配置、tool 调用、token 记账**均不受影响**；会话模型始终是原模型 |

**判定**：会话流畅、审计异步补上 = 隔离正确。若回合本身变慢/被打断 → 失败。

---

## B. 低分提醒（核心体验）

**目标**：推理质量低 → Tab 红点 + 悬停明细 + 可选系统通知。

制造低分场景：让模型"硬想"一个它无法精确知道的问题，例如：

> 请精确推算 1987 年 3 月 14 日出生的人在 2026 年 5 月 1 日的年龄（精确到天），并解释每一步，哪怕你没把握。

或一个明显诱导编造/绕圈的请求（以触发 `hallucination` / `redundancy` / `contradiction`）。

| 步骤 | 操作 | 预期 |
|---|---|---|
| B1 | 在某 Tab 跑一个低分回合 | 回合结束后该 Tab **出现红点**（`tabbar__audit-badge`） |
| B2 | 悬停红点 | 弹出 tooltip：**评分 + 问题数**（如 "推理质量低于阈值 — 评分 0.3，3 个问题"） |
| B3 | 检查系统通知 | 若 `notifications.enabled + audit_below`，收到系统通知（"Reasoning audit below threshold"） |
| B4 | 切到其他 Tab | **只有出问题的 Tab** 有红点；健康 Tab 无红点 |

**判定**：低分回合 → 该 Tab 红点 + 明细 tooltip = 通过。B3 若没通知，检查通知开关。

---

## C. 健康回合不误报

**目标**：干净推理不触发红点。

| 步骤 | 操作 | 预期 |
|---|---|---|
| C1 | 跑一个明确、有把握的回合（如"42 + 58 等于多少"） | **无红点**（score ≥ 阈值，`attention=false`） |
| C2 | 若该 Tab 之前有红点，再跑一个健康回合 | 红点**消失**（健康审计清除 attention 标记） |

**判定**：健康回合不误报、还能清掉旧红点 = 通过。

---

## D. 成本记账（P1）

**目标**：审计的 token 与成本被真实记录。

| 步骤 | 操作 | 预期 |
|---|---|---|
| D1 | 跑任意被审计回合 | 审计结果中 `EvalTokens` 为**非零**（真实 evaluator 消耗） |
| D2 | 若 `audit_model` 配了价格表 | `EvalCost` 为**非零成本**（经 `RateCardForModel` + `BuildQuote`） |
| D3 | 与会话回合 token 对比 | 审计 token **单独**存在（`ReasoningAuditTotals` 的 `EvalTokens`），**不并入**会话回合计费 |

**判定**：审计 token/成本有真实值且与会话计费分离 = 通过。

---

## E. content-free 契约

**目标**：思考文本绝不进入审计遥测。

| 步骤 | 操作 | 预期 |
|---|---|---|
| E1 | 触发任意审计后检查审计数据/日志 | 只含**计数/评分/耗时/token**，**无**原始思考文本 |
| E2 | 若观察 `audit:attention` 事件 | payload 仅 `tabID / score / issues / attention / elapsedMs`，**无**思考文本 |

**判定**：审计事件 content-free = 通过（这是 `REASONIX.md` 的硬契约）。

---

## F. 容错（shadow 语义）

**目标**：审计失败绝不影响回合。

| 步骤 | 操作 | 预期 |
|---|---|---|
| F1 | 把 `audit_model` 配成**无效/不存在**的模型 | 回合照常完成，**无红点、无报错、无卡顿**（审计静默失败） |
| F2 | 断网后跑回合 | 回合正常；审计失败不打扰主流程 |
| F3 | 把 `audit_model` 留空 | 回合正常，无任何审计（disabled 分支） |

**判定**：任何审计失败都不阻塞/回滚回合 = 通过。

---

## G. 多 Tab 并发（聚合隔离）

**目标**：所有活动 Tab 都被审计，互不干扰。

| 步骤 | 操作 | 预期 |
|---|---|---|
| G1 | 打开 2-3 个 Tab | 每个 Tab 独立显示自己的红点状态 |
| G2 | Tab A 制造低分、Tab B 制造健康 | Tab A 红点、Tab B 无红点（互不影响） |
| G3 | 关闭 Tab B | Tab A 红点不受影响；已关闭 Tab 的审计状态不干扰其他 Tab |

**判定**：各 Tab 审计状态独立、共享聚合器正确 = 通过。

---

## 快速通过标准（汇总）

一次完整验证至少应看到：
1. 回合完成后审计**异步**补上（无主流程延迟）。
2. 低分 → 该 Tab 红点 + 悬停明细（评分/问题数）。
3. 健康 → 无红点，且能清掉旧红点。
4. 审计有真实 `EvalTokens`（配置价格表则有 `EvalCost`）。
5. 审计事件 content-free（无思考文本）。
6. 审计失败/模型无效不影响回合。

---

## 若始终无红点

配置正确但无红点，按序排查：
1. `audit_model` 是否非空且有效（最常见原因）。
2. 该回合是否真产生了**思考链**（`Message.Reasoning` 非空）——无思考则不审计（`turnReasoning` 为空直接返回）。
3. 分数是否真的 < `audit_threshold`（健康回合本就不该有红点）。
4. `audit_enabled` 是否为 `true`。
